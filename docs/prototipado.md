# Herramientas e intercambio de prototipos

Escoge una herramienta cuando ayude a resolver una decisión de diseño. Para contrastar una secuencia sencilla puede bastar un boceto. Para explorar alternativas visuales, el flujo personal del Hub prefiere Google Stitch. Para validar contra componentes, variables y archivos ya aprobados por un equipo, usa su flujo de Figma. Ambos son opcionales. Las decisiones y notas de revisión siguen el [workflow de prototipado](../workflows/prototipado-validacion.md).

## Google Stitch

[Google Stitch](https://stitch.google.com/) es un lienzo web de Google Labs para generar e iterar pantallas y prototipos a partir de texto, imágenes y otros materiales. Trabaja con escenarios sintéticos y evita cargar materiales privados sin autorización. La [ficha del Hub](../catalog/google-stitch.yaml) representa el uso de la aplicación web. La referencia Git corresponde al repositorio oficial de skills bajo Apache-2.0. La implementación alojada tiene su propio alcance de licencia. [Anuncio de Google Labs](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-ai-ui-design/) · [Colección de skills](https://github.com/google-labs-code/stitch-skills/tree/9f4e828e77634e230978be45fec5501554dbe4b2)

- **Intercambio con `DESIGN.md`.** Google documenta su importación y exportación en Stitch. Es un archivo Markdown con convenciones y decisiones visuales como color, tipografía y espaciado. Google abrió el borrador de la especificación para facilitar intercambio. Vincula la versión del archivo al prototipo aprobado y mantenlo junto con estados y criterios de aceptación. [Anuncio de `DESIGN.md`](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-design-md/)
- **Exportaciones.** Google documenta salidas hacia Antigravity y Google AI Studio. La presentación inicial también describía HTML/CSS y Figma. Comprueba qué destinos expone la experiencia que estás usando y conserva una versión aprobada del artefacto. Un agente como Codex puede leer la documentación y los recursos locales resultantes. Revisa el código exportado, los recursos, permisos, dependencias y fidelidad antes de incorporarlos a una aplicación. [Exportación a herramientas de desarrollo](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-updates/) · [Presentación inicial y formatos](https://blog.google/innovation-and-ai/technology/developers-tools/google-ai-developer-updates-io-2025/)
- **Integraciones opcionales.** Google ofrece un SDK, un servidor MCP y skills de Stitch. Las skills orientadas a automatizar operaciones de Stitch pueden requerir esa conexión. Es un alcance distinto al del lienzo y del intercambio por archivos. El Hub propone primero el flujo de diseño y mantiene estas integraciones como opciones documentadas. [Integraciones oficiales](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-ai-ui-design/) · [Requisitos de las skills](https://github.com/google-labs-code/stitch-skills)

## Figma y sus skills

| Superficie | Acceso y alcance |
| --- | --- |
| Remota | `https://mcp.figma.com/mcp`, con inicio de sesión en Figma, cliente admitido y permiso sobre el archivo. Aporta contexto de diseño y puede escribir en canvas o enviar UI a Figma cuando las herramientas, el asiento y el archivo lo permiten. Para escribir fuera de borradores, la documentación indica un asiento Full. |
| Desktop | `http://127.0.0.1:3845/mcp`, con la aplicación abierta y habilitación local. Requiere asiento Dev o Full de un plan apto. Sirve para leer contexto de diseño y seleccionar frames. La escritura en canvas y el envío de UI son funciones del servidor remoto. |

En ambos casos revisa el plan, límites y permisos efectivos. Para implementar un diseño selecciona el frame y acceso mínimo. Las escrituras, cambios en un sistema de diseño, publicación de enlaces o traslado de activos requieren autorización separada. Figma lista Codex y Google Antigravity en su catálogo de clientes. Verifica la superficie concreta y las herramientas disponibles en la organización antes de elegir el método. Esta revisión fue documental. [Catálogo de clientes](https://www.figma.com/mcp-catalog/) · [Servidor remoto](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/) · [Servidor Desktop](https://developers.figma.com/docs/figma-mcp-server/local-server-installation/) · [Permisos y límites](https://developers.figma.com/docs/figma-mcp-server/plans-access-and-permissions/)

Figma documenta `figma-use` para crear o editar contenido de Design, `figma-spec` para especificaciones, `figma-code-connect` para relacionar componentes y `figma-code-workflows` para flujos de código. Se distribuyen por plugin en clientes compatibles o como descarga manual. Las instrucciones de las skills guían el uso de las herramientas que la cuenta ya tiene disponibles. Conservamos una sola [ficha de Figma MCP](../catalog/figma-mcp.yaml) y enlaces a sus skills oficiales, porque la selección en el Hub corresponde al flujo de diseño autorizado. [Skills oficiales de Figma](https://help.figma.com/hc/en-us/articles/39166810751895-Figma-skills-for-MCP) · [Herramientas y modalidades](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/)
